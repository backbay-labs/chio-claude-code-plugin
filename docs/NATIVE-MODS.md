# Native Chio interface

The 0.4.0-rc.4 candidate adds native session status, exact-action review, evidence,
recovery requirements and immediate commands. The kernel and trusted gateway
retain execution authority. A control in Claude records review intent; trusted
operator confirmation happens outside the host. The [controlled-task runbook](./CONTROLLED-TASKS.md) covers guided setup, completion evidence, continuation, the typed namespace and handoffs.

## Host contract

Use **Claude Code 2.1.287**, pinned in [host-contract.json](./host-contract.json).
The [declaration snapshot](../types/host/PROVENANCE.json) was generated by that
exact binary. Development loads may write fresh declarations under
`.claude-plugin/types`; the build uses the retained `types/host` snapshot.

The default rollout switch was off in the tested environment. Set
`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` for this process. `--bare` and
`disableAllHooks: true` prevent the user mod from loading. The native protected
profile enables only the staged native module and excludes compatibility command
hooks and Markdown commands. See Anthropic's
[creation guide](https://code.claude.com/docs/en/plugins/mods/create).

`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` also refuses mod HTTP requests on
this host. The protected native profile instead disables telemetry, error
reporting, feedback and updates individually; its OS sandbox permits only the
three selected loopback ports. It requires a successful scoped status read
before forwarding a model turn. Ordinary sessions using the aggregate switch
show disconnected status.

Mod failures are skipped by default. Chio's tool hook observes calls and preserves
their original results when observation fails. Its presence does not prove
resource confinement.

## Session interface

```text
Chio · kernel MCP tools only · authority 24m · 1 review · 0 unresolved
```

The operator service validates delegated authority at the kernel and verifies
retained completed outcomes against the exact request and trusted signer. Local
connection alone does not produce a live authority claim. Stale status loses
its live claim and review controls; disconnection clears the projection.

| Native command | Behavior |
| --- | --- |
| `/chio` | Open scope, retained work and controls |
| `/chio-status` | Print exact session identity, protected tools and dispatch fence |
| `/chio-doctor` | Distinguish control disconnection, expired authority, retained denial and uncertain original outcomes without submitting work |
| `/chio-review [request-id]` | Inspect an exact retained proposal |
| `/chio-evidence [request-id]` | Inspect outcome, evidence and recovery requirements |
| `/chio-revoke` | Request revocation of this exact kernel session; arguments refused |
| `/chio-task [template-id]` | Inspect task scope and request a new operator-defined task |
| `/chio-completion` | Inspect evidence tied to the current task's exact artifact |
| `/chio-continue request-id` | Continue an exact granted original operation without a planning turn |
| `/chio-outcome continuation-id` | Receive and acknowledge an original native-control result |
| `/chio-why request-id` | Inspect a retained decision reason and its provenance |

Commands register as immediate and do not start a model turn. Existing
`/chio:...` compatibility commands have different names and are excluded from
the protected native profile. Headless commands return text and an exit code;
panes open only in interactive sessions. Session identity is re-resolved on
every request and after clear, resume or fork. The compact review puts the exact
payload before its decision controls; a separate control expands evidence and
authority details. Panes scroll when an exact payload exceeds the viewport.

In an interactive session the mod shows a short notice when a new action awaits
review, a new original outcome becomes uncertain, live authority has five
minutes or less left (once per session), or a continued result is ready to
receive. The first projection after start or reconnect is a silent baseline.

The native doctor reads only the authorized session projection. It cannot inspect
the VM or prove storage integrity. In the trusted operator terminal, use the
separate infrastructure probe with an explicit profile, matching Docker context
and immutable image identity:

```sh
node scripts/doctor.mjs \
  --profile chio-native-qualification-x86 \
  --docker-context colima-chio-native-qualification-x86 \
  --image sha256:REPLACE_WITH_SELECTED_IMAGE_ID
```

It checks guest execution, root and Docker storage space, inodes, retained kernel
storage warnings, daemon identity and actual image inspection. Each probe has a
15-second bound. It returns `degraded` for retained filesystem repair warnings,
and `unavailable` for a failed probe. No image pull, container launch, disk repair
or protected action occurs. Passing these probes establishes current availability,
not filesystem integrity or workflow qualification.

The review shows the tool, full retained arguments, purpose, requested capability,
grant lifetime and decision state. Detailed information restrictions and budget
impact are **unavailable** in the pinned gateway projection; kernel policy still
applies. Revision binds the exact retained operation and frozen gateway authority
and configuration. This is not an independently verified policy-file revision.

Buttons request exact approval or decline. Alternative requests remain unavailable
until a linked-action contract is qualified, so they cannot consume an exact
review without a supported continuation. The service
returns `requested`, `authorityAccepted: false` and `dispatchPerformed: false`.
Previously recorded alternative requests remain visible to the operator and do
not block supported exact decisions. Semantic remedy generation and validation
are not implemented.

### Guidance for Claude

When a projection lists protected tools, the mod adds a `chio` context block to
the conversation's first message (and again after `/clear` or compaction). It
names the protected tools and tells Claude to stop at `awaiting_approval`,
never repeat a `pending` or `unknown` call, not repeat a denied call, and not
call `chio_resume` unless the user says the operator granted it. Guidance shapes
model behavior only; the kernel and gateway still enforce every decision.

## Operator service and ordinary sessions

Prepare an exact host session UUID and private gateway configuration using the
[operator runbook](./RESTRICTED-MODE.md). Start the trusted gateway with that
configuration; its journal must contain the frozen authority binding before
starting the control service. In a separate trusted terminal:

```sh
node scripts/control.mjs serve \
  --gateway-config /operator/private/gateway.json \
  --credential-output /operator/private/new-viewer.json
```

The new private file contains `url`, `token`, `sessionId` and `expiresAt`. Supply
only that viewer/intent credential as `CHIO_CONTROL_URL` and `CHIO_CONTROL_TOKEN`,
or the plugin's `control_url` and `control_token` options. Launch the pinned host
with that exact host session id:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 /absolute/pinned/claude \
  --session-id "$CHIO_HOST_SESSION_ID" --plugin-dir /absolute/plugin
```

An ordinary interactive session reports **kernel MCP tools only**. Native Bash,
file tools and other mods do not gain protection from this interface. Kernel and
operator credentials and the private journal stay outside Claude. The control
credential can read this session's authorized projection and record intent; it
cannot submit kernel authority decisions or dispatch a resource tool.
The compatibility hooks stay inactive in a session that `/chio:bond` has not
bonded, so loading the plugin does not deny native tools; see
[compatibility hooks](./RESTRICTED-MODE.md#compatibility-hooks).

## Confirm a decision outside Claude

Inspect the exact retained action and its intent in the trusted terminal:

```sh
node scripts/control.mjs status --gateway-config /operator/private/gateway.json
node scripts/control.mjs confirm \
  --gateway-config /operator/private/gateway.json \
  --intent "$CHIO_REVIEW_INTENT_ID" \
  --operator-file /operator/private/operator.json
```

To answer requests as they arrive, run the watch screen in the trusted
terminal instead:

```sh
node scripts/control.mjs watch \
  --gateway-config /operator/private/gateway.json \
  --operator-file /operator/private/operator.json
```

It prints each requested intent with its exact action and arguments, rings the
terminal bell, and asks `[y] confirm  [n] skip  [q] quit`. `y` runs the same
confirmation as `confirm`; `n` lets the intent expire. The watch never creates
or changes a decision and dispatches nothing. It requires an interactive
terminal.

The operator file contains an `adminToken` distinct from delegated execution
authority. Never supply it to Claude. Confirmation checks session, frozen
authority binding, exact arguments, state, revision, expiry and prior submission.
It uses the existing kernel approval API and verifies the exact signed decision
before retaining an approval artifact. HTTP success alone cannot mean granted.

Intent expires within 90 seconds or at delegated-credential expiry. Duplicate
and conflicting intent for one revision is refused. Submitted or uncertain
intent retains an exclusive submission fence: inspect its original authority
outcome before further action. The command dispatches no protected effect; a
grant does not dispatch. Use the native **Continue this exact action** control or `/chio-continue REQUEST_ID` to submit the original `chio_resume` through the existing gateway; direct MCP resume remains available.
The pane displays retained intent and hides repeated decision controls. Expired
or uncertain requests require operator inspection; this candidate does not
automatically renew them or resubmit an authority decision.

Revocation confirms the exact kernel session and pinned capability through its
session-trust endpoint. Requested revocation remains unconfirmed until that
response is checked. Compatibility `/chio:revoke [session-id]` instead revokes
the exact retained **passport artifact** and requires lifecycle confirmation
before clearing its bond. Compatibility `/chio:approve` reports `signed_intent`
or `decision_submitted`, never accepted authority. Compatibility receipt export
explicitly reports time-range scope, rather than claiming session filtering.

`node scripts/control.mjs report --gateway-config CONFIG --output NEW_FILE.md`
writes a Markdown report of the session: authority, operations, decisions,
continuations, task evidence and, with `--relay-events CONTROL/model-relay.json` (the launch's control directory,
recorded as `control` in `launch.json`; not a `control` folder inside the
profile), relay-metered model usage from that operator-supplied file. It references receipts by id and does not verify
them, and it never includes credentials or raw resource results.

## Protected native launcher candidate

| Mode | Purpose |
| --- | --- |
| `print` (default) | Existing restricted print contract, hooks/plugins disabled |
| `interactive` | Candidate terminal workflow with native commands and pane |
| `mod-print` | Candidate native loading and tool flow in a headless host |

Compute the reviewed native module identity:

```sh
node --input-type=module -e \
  'import {nativeModIdentity} from "./scripts/mod-profile.mjs"; console.log(nativeModIdentity(process.cwd()))'
```

Use the [existing launch arguments](./RESTRICTED-MODE.md), plus
`--mode interactive --mod-sha256 "$CHIO_NATIVE_MOD_SHA256"`. The launcher pins
the host, stages read-only mod sources outside guest-writable trees, and starts a
parent-owned scoped control listener. Its macOS sandbox allows the third exact
loopback port and a generated-types directory; no-fork confinement and exclusion
of operator credentials and journals remain. The relay accepts only the exact
selected MCP inventory and observes tool-result delivery before kernel ACK.

Interactive mode requires an actual terminal and pins its exact device. It uses
private guest session storage because `--no-session-persistence` is print-only.
The trusted parent initializes that fresh guest's onboarding, dark theme,
selected workspace trust and scoped relay-key response for the pinned host.
No global Claude profile or provider credential is copied. Existing profiles
remain refused; restart uses a fresh guest profile and the retained operator
journal. An authenticated control request for a different host UUID closes the
original gateway and terminates this protected launch. Clear was observed on
the actual pinned terminal host; resume and branch still require host lifecycle
qualification. Reusing a prior status read cannot keep the old launch active
after this session-change signal.

The selected relay also supports documented **text-only** mid-conversation
system messages on explicit supported model aliases, including
`claude-sonnet-5-5`. Bounded per-message effort requires the documented model
and beta contract. In the checksum-pinned host profile, observed
`per-turn-control-2026-07-01` requests also receive the documented
`mid-conversation-output-config-2026-07-01` header; message content is preserved.
This header compatibility rule is covered by a local fixture, not live provider
qualification. Inline tool changes, remote references, unsupported fields and
unsupported system-turn models remain refused. The older `claude-sonnet-5`
does not support those system messages; see Anthropic's
[system-message contract](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages)
and [per-message effort](https://platform.claude.com/docs/en/build-with-claude/effort#per-message-effort-beta).
Provider behavior requires separate qualification.

For the selected `claude-sonnet-5-5` and `claude-opus-5-5` aliases, the relay
preserves adaptive thinking and signed inline thinking history. It permits only
bounded thinking-history clearing, with its context-management beta; tool
clearing and compaction remain refused. `thinking.display: "updates"` requires
`thinking-display-updates-2026-08-18`, as specified in Anthropic's
[thinking display contract](https://platform.claude.com/docs/en/build-with-claude/thinking#controlling-thinking-display).
Unsupported structured title requests remain refused. Refused or failed work
requests cannot be counted as successful control-only completion.

**Interactive protected execution remains a qualification candidate.** Real
terminal operation and bounded mod file/process/network escape probes have
passed using a stubbed kernel context and local deterministic model. The
terminal fixture deliberately interrupts after the review is rendered. It does
not establish natural terminal shutdown, live provider behavior, the full
session lifecycle, signed live kernel decisions or resource recovery. Those
checks must pass with delivered artifacts before production qualification.

The parent relay records each forwarded conversation's model and
provider-reported token usage in `model-relay.json` and totals in `exit.json`
(`modelUsage`); `/chio-status` shows the totals as "relay-metered". These are
the provider's reported counts, not billing records, and are separate from
kernel tool budgets. `--model-token-budget N` stops new conversation requests
once input, output and cache tokens together reach N; requests already in
flight finish and can push the total past N (a soft stop), and token-count
requests are not refused. Interrupted streams count the usage reported before
the interruption (`usageComplete: false`). A budget stop ends the launch with
exit code 3 (`protected-work-incomplete`) and `modelUsage.budgetReached: true`.
Earlier tool results carried in the refused request are still acknowledged; the
refused request records no model context.

## Evidence and recovery

The pane and tool-result evidence link preserve authorization, host delivery and
verified execution as separate facts. Raw resource results and private approval
tokens are excluded from the status projection.

| Retained condition | Required path |
| --- | --- |
| Awaiting approval | Exact review, accepted grant, explicit resume |
| Denied | Separately authorized linked continuation; retain original denial |
| Pending or unknown | Reconcile original operation; retain dispatch fence |
| Verified completion without delivery/ACK | Recover original outcome; acknowledge delivery only |

No generic Retry control clears a fence or replaces an uncertain operation's
identity. Review executes no project code. The earlier recoverable-runtime
prototype is not promoted to a production dependency.

## Development

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run typecheck
npm run build
npm test
CHIO_CLAUDE_HOST=/absolute/pinned/claude npm run test:mods
python3 -m pip install --target "$CHIO_TERMINAL_LIBS" pyte==0.8.2 wcwidth==0.9.1
PYTHONPATH="$CHIO_TERMINAL_LIBS" \
CHIO_CLAUDE_HOST=/absolute/pinned/claude \
  node scripts/acceptance/native-mod-host.mjs /absolute/new-evidence-directory
npm run pack:release -- /absolute/candidate-directory
```

Native tests exercise Claude's event/drawing harness. Control tests use signed
authority fixtures. Cold installation and these tests do not establish complete
I01-I08 acceptance or one-effect/one-charge resource recovery.

Set `CHIO_TERMINAL_LIBS` to a new private test directory before the command
above. Python and the terminal emulator are acceptance-driver dependencies and
are excluded from the delivered runtime. To fetch the selected host into a new
separate path, use `node scripts/fetch-host.mjs --output /absolute/new/claude`.
The current evidence and remaining gates are in the
[native acceptance report](../acceptance/2026-10-03/controlled-workflows/REPORT.md).
The [dedicated environment and recovery report](../acceptance/2026-10-03/qualification-environment/REPORT.md)
records explicit context binding, actual enforcing-owner failures and shared
service preservation. Infrastructure recovery does not qualify those open
execution and durability contracts.

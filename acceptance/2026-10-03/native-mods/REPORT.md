# Native Claude Code mod candidate: 2026-10-03

**Version: 0.4.0-rc.1. Production qualification: incomplete.**

The native session interface and trusted control service are implemented. The
selected Claude host loads the mod, renders an exact review in a real terminal,
and holds the proposal without dispatching a resource effect. Live kernel
decisions, complete host lifecycle behavior and one-effect/one-charge recovery
remain release gates. Earlier host evidence does not qualify this candidate.

Confidence is **high** in the recorded host contract and fixture results,
**moderate** in the interactive integration beyond those cases, and **unknown**
for production recovery on the new native profile.

## Delivered behavior

- Immediate `/chio`, `/chio-status`, `/chio-review`, `/chio-evidence` and
  `/chio-revoke` commands, compact session status and a scrollable review pane.
- Exact arguments, purpose, capability and expiry before decision controls;
  retained authority and evidence details expand on request. Budget impact and
  detailed information restrictions are explicitly unavailable in this gateway
  projection.
- A parent-owned, session-scoped loopback API that reads authorized status and
  retains review intent. It receives no resource-dispatch or administrator
  capability from a button press.
- Trusted operator confirmation outside Claude. It checks frozen authority,
  exact action, revision, expiry and submission fence. Accepted approval requires
  the pinned SDK's verification of the exact signed kernel decision. This path
  has signed-fixture evidence, not a live-kernel qualification result.
- Distinct requested, submitted, granted, declined, confirmed and unknown
  control states. A grant still requires explicit gateway resume; it does not
  mean an effect committed. Alternative requests are retained for the operator;
  semantic remedy generation is not implemented.
- A candidate `interactive` launch contract and a `mod-print` probe contract.
  The default restricted print contract remains available. The new profile pins
  the host and mod, stages protected sources outside guest-writable trees, keeps
  the gateway and journal outside Claude, and confines native mod effect routes
  with the actual macOS sandbox.
- Session-specific compatibility controls. Revocation requires the exact
  passport artifact and lifecycle confirmation. Local receipt countersigning
  reports signed intent or submitted decision, rather than accepted authority.
- Recovery guidance that retains original operation identities and dispatch
  fences. No Retry control dispatches an uncertain operation again.

An ordinary plugin session reports **kernel MCP tools only**. Native Bash,
native file tools and other mods are outside that claim. The protected launcher
candidate has a separate, bounded MCP inventory and OS confinement contract.

and restart, and require independent observations of the resource and charges.

general Bash confinement remain outside this candidate.

## Packaging and publication boundary

The package uses npm's locked and vendored dependencies and self-contained
runtime bundles. The obsolete Bun lock referenced an unrelated local bridge
checkout and was removed. The
[cold-consumer driver](../../../scripts/acceptance/package-native.mjs) checks a
new offline cache, an installed runtime, a marketplace-style tree without
`node_modules`, strict selected-host validation and a disconnected native
command. Final tarball digests and consumer results belong in external candidate
sidecars; embedding a tarball's own digest would make the record self-referential.

`scripts/verify-native-qualification.mjs` rejects tag publication while this
record has `productionQualified: false`. Source checks, host fixtures and cold
installation cannot promote that flag. No merge, tag, npm publication or
production qualification is claimed by this report.

Reproduction and operator steps are in the
[native runbook](../../../docs/NATIVE-MODS.md). The original research remains in
[the proposal](../../../docs/research/2026-10-02-claude-code-mods.md).

# Native candidate 0.4.0-rc.5: fixture-level acceptance

**Version: 0.4.0-rc.5. Production qualification: incomplete (`productionQualified` is false).**

This record replaces the [rc.4 record](../../2026-10-03/controlled-workflows/REPORT.md)
as the description of the files on this branch. The rc.4 record described a
source tree that no longer exists: PRs #4 through #8 changed delivered runtime
code, so every rc.4 artifact pin is stale. rc.5 re-pins the version, the
artifact inventory and the pinned-host fixture results against the current
files. It is generated by
`scripts/acceptance/record-native-acceptance.mjs` from the checks recorded
below; [ACCEPTANCE.json](./ACCEPTANCE.json) is the machine-readable form and
[HOST-FIXTURES.json](./HOST-FIXTURES.json) the public host-case evidence.

## What rc.5 contains

Everything in rc.4, plus:

- PR #4: native correctness fixes (outside-tool observation binding and bounds,
  Unicode control neutralization in retained review text, cached-guidance
  invalidation, exclusive state-file creation, revocation validation,
  declaration packaging).
- PR #6: the review loop (new review and uncertainty arrival detection,
  quit-safe watch, prompt-acceptance-bound shared outcomes).
- PR #7: observability and completion evidence (provider-reported model usage
  metering and operator token budget in the relay, read-only operator
  Markdown session report, GitHub check-run collection bound to the exact
  commit, outside-Chio tool coverage in ordinary sessions).
- PR #8: adoption (labeled local demo against a confined fixture kernel with
  seeded signing, Chio lifecycle evals, DEMO labels on every surface) and the
  Codex review fixes. Codex review: 31 findings fixed (4 P0, 13 P1, 14 P2);
  see [the review comment](https://github.com/backbay-labs/chio-claude-code-plugin/pull/8#issuecomment-5988251728).
- PR #5: kernel requests and qualification-blocker research (documentation).
- A single-source version: `NATIVE_MOD_VERSION` in `scripts/mod-profile.mjs`,
  used by the native manifest and the restricted launcher, with a test that
  ties it to `package.json`, the lockfile and the plugin manifest.

## What this record does not establish

- It does not establish production qualification. The publication guard still
  refuses.
- The live owner observations recorded for rc.4 (approved native write, `fsync`
  SIGSYS, restart retention, HTTP 401 after restart, provider 429, Docker
  SIGSYS) were made against rc.4 artifacts and do not transfer to rc.5.
- The host cases use a stubbed kernel and a deterministic local model. They
  prove host loading, control flow and screens, not resource custody, kernel
  decisions or provider behavior.
- Only `hostContract` is marked qualified, and only as a live-host-contract
  fixture result for the selected darwin-arm64 host. Session lifecycle, kernel
  decisions, interactive protection, native recovery and cold install remain
  unqualified.
- The kernel source used for the 2026-10-03 live experiments is not retained
  in any reachable clone or remote branch, so those experiments cannot be
  reproduced as they stood.

## Open live gates

The six open blockers are listed in `ACCEPTANCE.json.qualificationBlockers`.
Five come from
[the qualification blockers plan](../../../docs/research/2026-10-04-qualification-blockers.md)
(tool metadata, Docker cage SIGSYS, native writer fsync SIGSYS, retained
credential revalidation, provider 429). The sixth is the missing kernel source
revision: the qualification kernel must be rebuilt from a selected, retained
revision before live evidence can be recorded against rc.5 artifacts.
